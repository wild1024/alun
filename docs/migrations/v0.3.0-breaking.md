# Alun v0.3.0 · 破坏性变更与升级指南

> 版本：`0.3.0`（22 个框架 crate 统一 `version.workspace = true`）
> 性质：**破坏性发布** 
> 来源：原 `docs/10`（演进建议）→ `docs/11`（升级报告）→ `docs/12`（feature 重构）→ `docs/13`（显式路由）→ `docs/14`（最优性评审）→ `docs/15`（破坏式优化实施报告）→ `docs/16`（新特性 cookbook）。上述 7 份演进/报告类文档已并入本文件，便于按版本查阅历史。
>
> 索引见 [docs/index.md](../index.md)。日常用法请以 [guides/getting-started.md](../guides/getting-started.md) 与 [guides/database.md](../guides/database.md) 为准。

## 0. 一句话结论

0.3.0 是 alun 从「能用但被迫改框架」到「扩展点标准化、资源访问上下文感知、安全默认」的破坏性跃迁。
本次共落地 **F1–F20 中的 18 项 + 2 项部分落地**，**0 项失败**；最关键的 4 处破坏性变更是：

1. **feature 默认最小 + 能力正交分层**（旧 `default = ["full"]` → 新 `default = ["core"]`，数据库驱动不再隐含）；
2. **注册机制彻底移除 `linkme`**（改走 `inventory`，`scan()` 重成默认主推写法，新增 `#[alun::routes]` + `App::module()` 显式通道）；
3. **handler 单一出口**（`ApiError` 下沉 `alun-web`，`WebError` 删除，`ResResult<T>` 成唯一签名，`DbError` 经 `From` 自动上转）；
4. **XLSX 真 OOXML、删除名实不符的旧 API**，以及 `db` 不再隐含 SQLite 等若干 API/语义收紧。

凡依赖 0.2 的项目，请按 §2 迁移对照表逐条核对。

## 1. 破坏性变更总表

| # | 变更 | 旧（0.2）| 新（0.3）| 影响 |
|---|---|---|---|---|
| B1 | 门面默认 feature | `default = ["full"]` | `default = ["core"]` | **最主要的不兼容点**：`alun = "0.3"` 默认只给 HTTP 能力，必须显式声明所需能力 |
| B2 | 数据库驱动隐含 | `features = ["db"]` 隐含 SQLite | `db` 只是**能力**，不含任何驱动 | 用到数据库处必须补 `sqlite`/`postgres`/`mysql`，否则建池报 `UnsupportedFeature` |
| B3 | `alun-task` 依赖 | `rdkafka` **必选**，开 `task` 即构建 librdkafka | `rdkafka` 可选：`task`=零外部构建链，`task-kafka`=需 CMake+C 工具链 | 纯 Windows 工具链下 `task` 现在可用（旧版直接 `os error 193`） |
| B4 | 注册机制 | `linkme::distributed_slice` 依赖链接器段 | `inventory` 收集（不依赖段）+ 显式 `#[alun::routes]`/`App::module()` | 旧 `linkme` 在部分工具链静默失效（路由全 404 无报错）；现已根治 |
| B5 | handler 错误出口 | `WebError` + 多出口 | `ResResult<T>` 唯一出口；`ApiError` 在 `alun-web`；`DbError` 经 `From<DbError> for ApiError` 自动上转 | 数据层 `?` 直接上抛；5xx 对前端模糊化（详情进日志） |
| B6 | XLSX API | `Export::to_xlsx` 实为 BOM+CSV；有空壳 `ExportFormat` 枚举 | 删除名实不符 API；新增 `xlsx` feature：真 OOXML（rust_xlsxwriter/calamine） | 未开 `xlsx` 时 `to_xlsx_*` 根本不存在，不会退化成 CSV |
| B7 | `Expr::Raw` | 变体 `pub`，可任意构造 → 注入后门 | 变体字段**私有化**，仅 `Expr::raw_trusted`/`raw_trusted_bound` 可构造 | 每次调用进 `alun_db_raw_sql_total` 计数 |
| B8 | `TokenClaims` | 8 个固定字段写死 | 新增 `#[serde(flatten)] extra: HashMap`，配套 `ClaimsBuilder` | 手工构造 `TokenClaims {..}` 字面量需补 `extra: Default::default()` |
| B9 | 版本号 | 各 crate 版本互不相同（0.1.x~0.2.0） | 全部 `0.3.0`，`version.workspace = true` | 文档/示例统一 `alun = "0.3"` |
| B10 | 预设命名 | `full-lite`/`full-all` | `mini` ⊂ `lite` ⊂ `full`（能力严格递增） | `full-lite`→`lite`，`full-all`→`full` |

> **防倒退**：`ci/check_feature_discipline.sh`（15 条断言）守护「默认集不得变重 / 预设不得混入重型依赖 / `full` 不得变空」，建议接入发布流程。

## 2. 迁移对照表（破坏性写法）

| 旧写法（0.2）| 新写法（0.3）| 说明 |
|---|---|---|
| `alun = "0.2"`（默认 full）| `alun = { version = "0.3" }`（默认 core）| 必须显式加能力 |
| `features = ["full"]` | 不变 | `full` 仍存在，语义等价于旧 `full-all` |
| `features = ["full-lite"]` | `features = ["lite"]` | 预设改名 |
| `features = ["full-all"]` | `features = ["full"]` | 预设改名 |
| `features = ["db"]` | `features = ["sqlite"]`（或 `postgres`/`mysql`）| **`db` 不再自带 SQLite** |
| `alun-db` 默认使用 | 需显式 `features = ["sqlite"]` | 驱动不再默认 |
| `features = ["task"]`（含 Kafka）| 不变，但语义收窄为"任务模型" | 要 Kafka：`features = ["task-kafka"]` |
| `Export::to_xlsx(cols, rows)` | `Export::to_xlsx_bytes(cols, rows)` / `to_xlsx_typed` / `to_xlsx_workbook` | 需 `xlsx` feature |
| `WebError::*` | `ApiError::*`（`alun::prelude`）| `WebError` 已删 |
| `alun_core::api::*` | `alun_web::api::*` | 经 `alun` 门面 `prelude` 路径不变 |
| `linkme` 显式注册 | 无需，改用 `#[alun::get]`+`scan()` 或 `#[alun::routes]`+`module()` | 框架已移除 linkme |

**凡用到数据库处，必须补一个驱动 feature**——只写 `db` 会得到"可编译、运行时报 `UnsupportedFeature`"的隐蔽状态，这是升级后最常见的坑。

## 4. 关键安全修复

### 4.1 封 F2 跨租户泄漏（P0）
旧守卫只看「是否出现过任意一个 `/*tenant*/` 占位」，只标主表漏标 JOIN 从表时 `c` 不过滤却放行 → **静默跨租户泄漏**，且文档曾错误声称"漏标会被拒绝"。

- 新守卫：Scoped 上下文下**必须** `tenant_bound && annotated`（每张租户表都标注）才放行；
- 新增 `ModelQuery::raw_tenant_annotated()`：调用方**显式承诺**"每张租户表都已标注"，未调用者一律拒绝；
- 错误信息改为可行动：优先引导结构化联查，其次说明「占位 + 显式承诺」写法。

### 4.2 三条 fail-closed 底线（多租户）
1. 租户模型在**无租户上下文**时查询 → 报错，绝不静默放行全量；
2. 租户模型的**原生 SQL** 在 `Scoped` 上下文下 → 报错，除非显式 `raw_tenant_annotated()` 承诺；
3. 鉴权规则未匹配到放行项 → 拒绝。

### 4.3 结构化联查从机制上消灭泄漏（F7）
`ModelQuery::join::<U>(kind, on)` 用 `join_scope_for::<U>()` 解析从表租户作用域并自动注入——从表模型由类型参数 `U` 枚举，**不存在"漏标一张表"**。租户谓词追加在 `ON` 之后（非 `WHERE`），保证 `LEFT JOIN` 语义正确。

### 4.4 安全可观测性（F10）
`alun_tenant_scope_missing_total` / `alun_raw_sql_tenant_unbound_total` 两个计数器直接挂钩 fail-closed 分支，让"每次请求都在撞守卫"这类问题在监控层可见（单测永远是绿的，只有计数能暴露）。生产务必将二者非 0 视为告警。

## 5. 注册机制：两条通道并存

- **`#[alun::get/post/...]` + `App::scan()`**：宏展开为 `inventory::submit!`，链接期无关，**默认主推**写法（日常零注册代码）。
- **`#[alun::routes]` + `App::module()`**：宏展开期生成纯 Rust 注册函数，**不依赖任何链接器段**，对集成测试夹具 / 库形态分发（一个 crate 无法指望使用方收集到自己的 handler）/ 需掌控装配顺序的场景成立。

> 历史注记：原 `.cargo/config.toml` 的 `-Wl,--no-gc-sections` 兜底**已删除**——`inventory` 不依赖链接器段，收集在所有工具链上均成立。决定性验证：删除该兜底后 `alun-web` 单测仍全绿。
> 集成测试里若路由定义在 lib 中且未被测试代码引用，目标文件不会被抽取（成因 B），此时请用显式注册通道。

## 6. feature 分层模型

默认 `core`（路由 + 中间件 + 配置 + 日志），能力逐层叠加；能力与驱动分离。

| 层 | feature | 说明 |
|---|---|---|
| L0 | `core`（默认）| 最小 HTTP 服务 |
| L1 | `cache` / `template` / `plugin` / `fs` / `sse` / `xlsx` / `xss` | 相互独立 |
| L2 | `db` / `sqlite` / `postgres` / `mysql` | 能力 vs 驱动分离，写驱动即隐含 `db` |
| L2 | `fs-local` / `fs-minio` | 存储后端 |
| L2 | `metrics` / `metrics-prometheus` | 埋点（no-op 安全）/ Prometheus 导出 |
| L3 | `kafka` / `task` / `task-kafka` | 仅 `task-kafka` 需 CMake + C 工具链 |

预设（能力严格递增 `mini ⊂ lite ⊂ full`）：

```toml
alun = { version = "0.3", features = ["mini"] }   # SQLite + 本地缓存，零外部服务
alun = { version = "0.3", features = ["lite"] }   # PostgreSQL + 缓存 + 插件 + 本地存储，单库生产推荐
alun = { version = "0.3", features = ["full"] }   # + MySQL + Kafka + Task(Kafka) + MinIO + SSE + 可观测 + XLSX + 模板
```

## 7. 未做项与后续建议（按性价比）

| 项 | 现状 | 建议 |
|---|---|---|
| `Expr::Subquery`（关联子查询）| 未做 | 报表类先用 `join` + 占位原生 SQL |
| `Plugin::migrations()` | 未做（WebPlugin 只贡献 routes/permission/no_auth）| 插件迁移走项目 `migrations/`，或在 `Plugin::start()` 内执行 |
| WebSocket | 未做（只做 SSE）| 双向通信直接用 `axum::extract::ws`，鉴权走 subprotocol |
| 只读副本自动路由 | **明确不做**（主从延迟 + 事务内读语义不可推理）| 用命名数据源 `db_named` + 显式只读账号 |
| `insert_on_conflict`（UPSERT）| 未做 | 用 `Row` + `execute_owned` 自定义 `ON CONFLICT`，或 `(tenant_id, code)` 先查后写 |
